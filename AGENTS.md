# Developer and AI Agent rules

1. Solve the user's friction: connect the selected browser page to their desktop tools, and keep standalone edit/copy/save useful. Do not create a catch-all Chrome app.
2. Keep this repository, extension version, release ID and update stream **independent** from `eaopen/local-bridge` and the existing CloudFile Chrome extension. No takeover of CloudFile browser routes or native host registrations.
3. All page-origin requests from content scripts are untrusted; service worker rechecks Chrome-reported sender origin and permits only typed read-only discovery **unless the user separately grants enterprise AI to that exact Web origin**. In the latter case, only `enterprise.pi.run` with the same-origin app backend API path, short-lived scoped enterprise ticket and bounded text prompt is allowed. Webpages may never choose a Native Host, EXE, shell command, browser cookie or long-lived token. Only the user popup may choose a separately installed trusted Native Messaging Host.
4. Standalone must work if local host is missing. Optional Native Messaging must be authorized by the user and installed separately. Popup content sending remains direct user-triggered; a separately approved enterprise site may execute only its scoped text-only AI capability without repeat approval.
5. Avoid cloud telemetry, remote code, page-wide scraping and unrelated browser permissions; follow Chrome Web Store Manifest V3 single-purpose and accurate privacy standards.
6. Mark experimental/placeholder native integration honestly. Do not claim a reference host has executed a Local Bridge/Agent task.
7. Prefer narrow tests and one true browser scenario; no overly broad abstraction or governance layers.
8. The optional `context.summarize` path is **popup user-click only**. Website AI is a different, separately granted `enterprise.pi.run` capability, strictly bound to the app's own origin and backend ticket; it never enables arbitrary local tools or the user's personal AI model credentials. A locally installed Pi CLI may call a network-based enterprise model and must not be described as offline.

9. Web AI Relay is **manual clipboard/open/return**, not a chatbot integration or model gateway. Do not add Web Chat DOM scraping, auto-login, API/token extraction, auto-send, automatic MCP execution or 9Router-like quota routing. No Local Bridge/WeChat installation requirement; the optional `relay.return` only stores a user-reviewed reply linked to a source/task reference.

10. Enterprise Web→Pi requires explicit site-scoped AI permission and a ticket issued by the site's authenticated backend, checked on each request. No DOM chat scraping, no ChatGPT consumer-web API emulation, no automatic MCP/shell/file tool execution, no permanent browser credential cache. Do not mark it production-ready before real SSO/Chrome GUI E2E.
